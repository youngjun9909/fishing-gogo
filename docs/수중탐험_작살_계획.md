# 수중 탐험: 작살 사냥 · 수중 도감 · 보스 계획

## 확정된 방향 (사용자 결정)

- 수중에서 **작살을 던져 물고기를 잡는다**. 조개 같은 가만한 것은 가까이 가서 **채집 키**로 줍는다.
- 잡은 것은 **코인으로 판매 + 강화석이 나옴 + 도감 등록**. 지상 낚시와 시간당 수입을 비슷하게 맞춘다(수치는 사용자가 따로 적어 줄 예정 → 받으면 3단계에 반영).
- **수중 도감은 탭을 따로** 둔다.
- 구역(6개)마다 **18종**: 일반·희귀·매우 희귀 합쳐 15 + 전설 2 + 신화 1. 합계 108종. 구역 테마에 맞는 물고기.
- 일반은 떼로 다니고, **희귀·매우 희귀는 무리 없이 단독**으로만 나온다(낚시와 균형).
- **보스급(전설·신화 크기)**은 아주 가끔 나온다. 나오면 채널 전체에 "보스가 나타났다"만 알린다(위치 없음, 맵이 작아 가면 보인다).
- **보스는 작살로 피해를 입힌다**. 약점이 일정 간격으로 나타나는 체크포인트 방식. 보상은 **기여도 순**(코인·강화석·칭호).
- **15명이 같은 물고기를 함께 보고 경쟁**한다. 사람이 많을수록 잡기 쉬우니 **판매가가 자동 조절**(많으면 약간 높고, 혼자면 약간 낮게).
- 보물 상자: 꽝 / 코인만 / 강화석만 / 둘 다 / 미끼 / 진주(수집품) 랜덤. 상자 종류는 나무·은·금.
- **빼는 것**: 산소 게이지, 깊이 구역, 보스 지도, 꾸미기 아이템, 작살 임시 강화.

## 설계 결정 (제가 정한 것, 틀리면 알려 주세요)

### 조준·던지기 (PC·휴대폰 공통)
- **조준점은 화면 중앙 십자선**(= 카메라 방향). 휴대폰은 이미 화면을 끌어 시점을 돌리므로 따로 조준 조작이 필요 없다.
- 던지기는 PC는 **클릭**, 휴대폰은 **던지기 단추 하나**.
- 실패 요소(사용자 승인):
  - 조준 흔들림: 십자선이 숨 쉬듯 흔들림. 가만히 있으면 줄고 이동 중엔 커짐.
  - 비행 시간: 작살이 날아가는 동안 물고기가 움직임 → 앞서 쏘기. 멀수록 어려움.
  - 놀람: 가까이 급접근하면 도망. 희귀할수록 예민.
  - 던진 뒤 회수 시간(연타 방지).
  - 중대형 이상은 꽂힌 뒤 **짧은 힘겨루기**, 줄이 끊기면 놓침.
- 등급별로 맞는 범위(몸 크기 판정)와 속도를 달리한다(낚시의 `zoneWidth`·`cursorSpeed`와 같은 역할).

### 물고기 동기화 (15명 공유·경쟁)
- 서버가 물고기를 **생성만** 한다: `{id, 종, 구역, 시작시각, 시드}`.
- 이동 경로는 **시드와 시간으로 계산하는 정해진 함수**라서 서버와 모든 클라이언트가 같은 위치를 계산한다(위치를 계속 보내지 않음 → 서버 부담 작음).
- 던질 때 클라이언트가 `{던진 시각, 방향, 위치}`를 보내면 **서버가 그 시각의 물고기 위치로 맞았는지 판정**한다. 먼저 유효하게 맞은 사람이 가져간다. 지연 보정은 낚시 타이밍과 같은 방식(허용 상한 400ms).
- 조개·상자는 서버가 위치와 남은 수를 관리하고, 먼저 채집한 사람 것.

### 작살 강화
- 낚싯대처럼 **레벨 하나가 모든 능력을 조금씩 올린다**(사거리·조준 안정·비행 속도·회수 속도·줄 강도). 탐지 범위(상자 반짝임)는 후반 단계에서 추가.
- 특정 단계마다 **외형 변경**. 판매가 보너스는 넣지 않는다(낚싯대와 겹침).
- 강화석 사용·확률 구조는 기존 강화창(Forge)을 재사용한다.

### 판매가 자동 조절
- 판매가 = 기본가 × 채널 인원 배율. 예: 1명 0.85 → 15명 1.15(선형, 시작값). **판매하는 순간의 채널 인원**으로 서버가 계산한다.
- 수치는 사용자가 적어 줄 가격 균형표를 받아 맞춘다.

### 보스
- 구역별 출현 간격은 길게(예: 20~40분 중 무작위, 시작값). 나타나면 채널 전체에 알림.
- 체력은 **약점 맞히기**로 깎는다: 약점이 몇 초 간격으로 다른 곳에 떴다 사라지고, 맞히면 큰 피해, 몸통은 작은 피해. 제한 시간(예: 3분 + 잡힐 때까지) 안에 못 잡으면 도망(보상 없음 또는 참가상).
- 최소 참여 조건(한 번 이상 맞힘). 기여도 순으로 코인·강화석·칭호 차등. 칭호는 첫 처치·누적 횟수.

### 콘텐츠 제작량 줄이기
- 108종 전부 고유 모델은 너무 크다. **일반·희귀는 기본 체형 6~8종을 색·무늬·크기로 변형**해 만든다.
- **매우 희귀·전설·신화는 고유 모델**(체형 자체가 다름)로 간다. 구역당 15종 중 일반 8 / 희귀 5 / 매우 희귀 2로 잡으면 고유 모델은 매우 희귀 12 + 전설 12 + 신화 6 = **30종**.
- 희귀도 완전 변형만 쓰지 않고, 기본 체형에 지느러미·꼬리·장식 같은 **부품을 달리 붙여** 실루엣이 달라 보이게 한다.
- 구역 순서는 방침대로 **아틀란티스부터**, 한 구역을 끝까지 만든 뒤 다음으로.

## 단계

| 단계 | 내용 | 끝나면 되는 것 |
|---|---|---|
| 1 | 작살 던지기 코어 + 서버 판정 + 아틀란티스 일반 물고기·조개 | 친구들과 잡아 볼 수 있음 |
| 2 | 수중 도감 탭 + 판매(인원 배율) + 강화석 드랍 | 잡은 것이 도감·코인으로 이어짐 |
| 3 | 작살 강화(Forge 확장) + 가격 균형 반영 | 진행도 순환 완성 |
| 4 | 보물 상자 + 상자 종류 + 진주 | 탐험 보상 |
| 5 | 희귀·매우 희귀 단독 출현, 전설·신화 | 등급 완성 |
| 6 | 보스(약점 체크포인트, 채널 알림, 기여도 보상, 칭호) | 채널 이벤트 |
| 7 | 나머지 5개 구역 물고기·모델 채우기 | 108종 |

## 시작 전에 확인할 것
- 서버 `UnderwaterRoom.ts`와 클라이언트 `underwater.ts`의 현재 구조(물고기·상자 자리가 있는지), 공유 `SPECIES`에 수중 종을 넣는 방식(ID 구분)과 `catches`/`codex` 저장 재사용 가능 여부.
- 수중 탐험 파일이 아직 커밋되지 않았고 브랜치 병합이 미정이라, **1단계를 시작하기 전에 이 정리부터** 해야 한다.
- 가격 균형표(사용자 제공 예정)를 3단계 전에 받는다.

## 위험·한계
- 수치(판매 배율, 보스 출현 간격, 확률)는 시험 플레이 없이 정한 시작값이다.
- 서버 판정은 낚시처럼 지연 보정이 필요하다. 물고기 경로 함수가 서버·클라이언트에서 완전히 같아야 하므로 단위 시험(`shared`의 순수 함수)을 둔다.
- 15명이 같은 물고기를 두고 경쟁하므로 사람이 몰리면 먼저 맞힌 사람 판정이 중요하다. 서버가 판정 순서를 정한다.
