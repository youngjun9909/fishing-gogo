# 옷 종류별 디자인 규격

출처: `shared/src/items.ts`의 `slot: "outfit"` 항목 3개(확인함).

| id | 이름 | 가격 |
|---|---|---|
| `outfit-overalls` | 멜빵바지 | 300 |
| `outfit-raincoat` | 노란 우비 | 500 |
| `outfit-hanbok` | 한복 | 900 |
| (기본, id 없음) | 노란 스웨터+회색 바지+노란 운동화 | 시작 옷 |

## 0. 슬롯 구조: 확인된 것과 결정 필요

- 확인: `items.ts`에는 상의/하의/신발 슬롯이 따로 없고 `outfit` 슬롯 하나다. 현재 코드(`character.ts`)는 옷 하나를 고르면 스웨터색, 바지색, 신발색(우비일 때만 바뀜)을 한꺼번에 바꾼다.
- 따라서 이 문서의 옷 종류는 **세트(상의+하의, 필요하면 신발)**로 규격을 쓴다.
- **결정 필요(미확인)**: 신발을 세트에 포함할지, 별도 슬롯으로 둘지. 기본 제안: 신발은 기본 운동화 고정, 우비만 노란 장화로 교체. 사용자가 정해 주면 갱신한다.
- 코드 변경은 이 세션 범위 밖이다.

## 1. 공통 규칙

- 모든 옷은 기본 옷과 같은 방식: 몸에서 분리된 속 빈 메시, 몸보다 크고 두꺼움, 단색 배경, 정면/측면/뒤, 그림자 없음([top.md](top.md) 규칙 준용).
- 기본 몸과 같은 T자 자세로 그린다.
- 로고·글자·복잡한 무늬 금지(색 변경과 폴리곤 때문). 무늬가 필요하면 색 구역(영역)으로 나눈다.
- 한국어/영어 프롬프트 형식은 상의 문서를 따른다. 아래는 각 종류의 **디자인 규격**과 **프롬프트 핵심 구절**만 적는다.

## 2. 노란 우비 (`outfit-raincoat`)

| 항목 | 규격 |
|---|---|
| 형태 | 헐렁한 A라인 우비 상의 + 밑으로 내려오는 길이(엉덩이~허벅지 윗부분). 바지는 별도로 같은 노랑 방수 바지, 또는 우비가 길어 바지를 덮음 |
| 후드 | 등 뒤로 내려 접은 상태 또는 머리 뒤로 걸친 상태. 쓴 후드는 머리카락·얼굴과 충돌하므로 **내린 후드**가 기본 |
| 앞 | 가운데 단추 4~5개 또는 스냅 줄(큼직한 둥근 단추, 작은 부품 금지) |
| 소매 | 통 넓고, 손목에 고무밴드로 조인 모양 |
| 소재 느낌 | 약간 광택 있는 매끈한 비닐 느낌(반사는 약하게) |
| 색 | 밝은 노랑. 기본 코드 색은 `#f5d54a`. 기본 스웨터 `#f6d35a`와 구분하려면 우비는 **더 진한 노랑/황금빛** |
| 신발 | 노란 고무장화 권장(`#f5d54a`) — 코드가 우비일 때 신발색도 바꾸고 있음(확인함) |
| 프롬프트 핵심 | `oversized yellow rain coat, A-line, hood folded down at the back, large round buttons, elastic cuffs, smooth glossy-matte vinyl` / 노란 비옷, 헐렁한 A라인, 후드를 뒤로 내림, 큼직한 둥근 단추 |

주의: 후드가 머리카락 부품과 겹친다. 후드는 **어깨 위에 얹힌 늘어진 천**으로 만들고, 머리카락 영역(머리 위쪽)을 침범하지 않게 한다.

## 3. 한복 (`outfit-hanbok`)

| 항목 | 규격 |
|---|---|
| 형태 | 저고리(짧은 상의, 허리 위 길이, 고름이 앞에서 리본 모양) + 치마(풍성하게 퍼지는 긴 치마, 종아리~발목 길이) |
| 저고리 | 소매는 넓게 곡선(도련), 깃과 동정(흰 칼라 선) 표현, 가슴 아래에서 고름 리본이 늘어짐 |
| 치마 | 둥글게 퍼지는 종 모양. 큰 주름 몇 개만. **다리 두 개가 따로 보이지 않는다** → 하의와 다리통 구조가 다르다 |
| 색 | 기본: 상의 분홍(`#f4a3b8`), 치마 파랑(`#6f9be0`) — 현재 코드의 색(확인함) |
| 무늬 | 없음. 깃·고름·동정의 선 색만 다르게(색 영역) |
| 신발 | 기본 운동화 유지 제안(미확인: 사용자 결정 필요) 또는 별도 꽃신은 후순위 |
| 프롬프트 핵심 | `Korean hanbok, short jeogori jacket with long ribbon goreum, wide flowing skirt, hollow, no body` / 한복 저고리와 풍성한 치마, 고름 리본, 속 빔 |

주의: 치마는 다리 전체를 감싸므로 기본 하의 규격(두 다리 분리)과 달리 **한 덩어리 종 모양**이다. 걷기 애니메이션에서 다리 뼈를 따라 흔들릴 때 치마 가중치가 중요하다([game-integration.md](game-integration.md)).

## 4. 멜빵바지 (`outfit-overalls`)

| 항목 | 규격 |
|---|---|
| 형태 | 흰/아이보리 긴팔 셔츠(`#f4f1e8`) + 파란 데님 멜빵바지(`#4f7cc4`) |
| 멜빵 | 어깨에 걸치는 넓은 끈 2개, 앞 가슴 위 사각 가슴판(빕) 1개, 큼직한 단추 2개(작은 부품 금지, 크게) |
| 바지 | 기본 하의와 같은 와이드 또는 약간 좁은 통, 밑단 접힘 |
| 셔츠 | 기본 스웨터와 같은 헐렁한 소매, 끝단 밴드는 얇게 |
| 색 | 셔츠 흰, 멜빵바지 파랑. 데님 질감은 단순한 회색조 주름 정도 |
| 프롬프트 핵심 | `blue denim overalls with wide straps and a square bib pocket over a loose white long-sleeve shirt, large round buttons, hollow, no body` / 파란 데님 멜빵바지, 넓은 멜빵과 사각 가슴판, 흰 긴팔 셔츠 |

주의: 멜빵바지는 상의(셔츠)+하의(바지) **두 부품을 합친 세트**다. 부품 둘로 따로 만들어도 되고, 한 메시로 만들어도 된다(부품 둘 권장: 셔츠는 기본 상의 형태를 재사용 가능).

## 5. 색 변경 방식 (회색조 마스크 + 게임에서 색 입히기)

목적: 옷 한 벌(메시 1개)로 여러 색을 만들기. 처음부터 필요한 것은 아니며, **우선은 색이 구워진 옷**으로 시작해도 된다.

### 방식
1. 옷 그림을 **회색조(흑백) 밝기 정보**로 만든다. 주름 그림자는 명암으로 남긴다.
2. 색을 바꿀 영역별로 **마스크 이미지**(흑백, 흰색=이 부분 색 입힘)를 따로 만든다. 예: 스웨터 몸통 / 소매 끝단 / 밑창(고정 흰색).
3. 게임(`three.js`)에서 재질을 만들 때 영역 색을 밝기 위에 곱해서 칠한다. 예: `최종색 = 회색조 × 입힐 색`.
4. 색 목록은 `client` 쪽 팔레트 배열로 관리한다(코드 작업, 이 문서 범위 밖).

### 제작 조건
- 영역은 3개 이내로 단순하게(예: 몸통, 끝단, 안감).
- 밑창, 단추, 끈 같은 **색이 고정된 부분**은 마스크 밖(흰색 고정)으로 둔다.
- 얼룩·무늬는 회색조에 섞지 않는다(곱셈 시 색이 탁해짐).
- 회색조는 **중간 회색 기준**으로 밝은 곳은 흰 쪽, 그림자는 어두운 쪽이 되게. 너무 어두운 그림자는 색을 죽인다.

### 현실 점검 (미확인)
- Tripo 결과물은 보통 색이 텍스처에 구워져 나온다. 회색조/마스크 분리는 **Tripo 입력을 회색조 그림으로 넣고**, 결과의 텍스처를 그대로 회색조로 쓰는 방법이 가장 쉽다(마스크는 같은 그림에서 영역을 칠해 만든다). 이 방식이 실제로 잘 나오는지는 해보기 전까지 **미확인**.
- 대안(더 단순): 옷마다 색이 다른 버전 2~3개를 따로 생성. 비용(크레딧)은 늘지만 작업은 쉽다.
- 현재 게임 코드는 재질 이름으로 단색을 칠한다(확인함). 새 옷 메시에서도 **재질 이름을 `Top`, `Bottom`, `Shoe`, `Sole`처럼 고정**해서 규칙을 이어가면 코드를 바꾸기 쉽다(제안).

## 6. 사용자에게 필요한 결정

1. 신발은 세트에 포함? 별도 슬롯?
2. 색 변경 기능을 이번에 넣을지, 나중으로 미룰지.
3. 세트 옷(한복·멜빵바지)을 부품 둘로 나눌지, 메시 하나로 만들지.
